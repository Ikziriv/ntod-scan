# ntod-scan — agent notes

Rust 2024 workspace. LAN discovery & packet tools, local-first.
Scan only systems you own or are permitted to test.

## Layout

- `crates/core` — scanning engine library (`scan`, `discover`, `wifi`,
  `arp`, `oui`); pure library, no UI/HTTP.
- `crates/capture` — packet capture (pcap/raw-socket backends; `pcapr`
  reads .pcap/.pcapng, `pcapw` writes classic pcap). `start()` yields
  `RawFrame{ts, linktype, bytes}` — decode to `PacketEvent` via
  `decode::decode_frame`, or feed the analysis engine.
- `crates/analysis` — pcap triage engine (`analyze()` file,
  `analyze_live()` timed capture): bidirectional flows, L7 dissectors
  (DNS, HTTP, TLS+JA3, DHCP), credential extraction, and deterministic
  detectors (port-scan, DNS-tunnel, ARP-spoof, beacon, TLS cert hygiene).
  Same report model for live and file input. `history` is a bounded
  JSON device/baseline store (`$NTOD_DATA_DIR` or `~/.ntod-scan`);
  only *live* captures update it — uploads never touch local history.
- `crates/api` — axum HTTP+WS seam (`/api/*`, `/ws`) plus the
  server-rendered web UI under `src/web` (maud pages, `/partials/*`
  htmx fragments, `/sse/*` HTML event streams); `ServeDir` stays as
  the static-asset fallback.
- `crates/cli` — `ntod` binary (clap).
- `crates/tools` — external-tool adapters (nmap `-oX` XML, masscan `-oL`,
  `tcpdump -w -` pcap stream, airodump-ng remote CSV) behind a bounded
  subprocess runner: argv only (no shell), deadline kill, capped output.
  `Backend` runs the same argv locally, in WSL, or over SSH; airodump's
  files come back through a fixed `sh -c` fetch script. `tools` cargo
  feature on cli+api.
- `crates/ai`, `crates/control`, `crates/proxy` — optional seams.
- `apps/web` — static assets only: vendored `app.css`, `ntod.css`,
  `ntod.js` (theme menu + report tab/drill JS), `vendor/` (htmx +
  sse ext), and `islands/` — generated by `npm run build` in
  `apps/islands` (Svelte, gitignored; the sniff view's packet-rate
  island is the only component).
- `examples/demo.pcap` — synthetic capture (all detectors fire) for
  docs and the README; regenerate with `scripts/gen-demo-pcap.py`.
- `scripts/capture-shots.mjs` — re-captures `docs/screenshots/*.png`
  from a running `ntod serve` via Edge + `puppeteer-core`
  (`npm i --prefix .shots puppeteer-core`; `.shots/` is gitignored).

## Conventions

- Bounded everything: capture feeds, worker counts, timeouts.
- `Result` for expected failures; never panic on network input.
- Design system source of truth: `DESIGN.md` (shared with ntok-scan —
  `apps/web/app.css` is vendored from ntok verbatim; put ntod-only rules
  in `ntod.css`, never edit the vendored file for app features).
- Remote-provided strings (SSIDs, hostnames) are untrusted — escape
  before `innerHTML`.

## NCC (agent harness)

- `.ncc/skills/` is the canonical project skills dir — commit it.
- `.ncc/memory/` is the local NCC memory vault — never committed.
  `ecc memory` resolves `ECC_MEMORY_PROJECT_ROOT` relative to **cwd**
  and silently misses the vault from subdirectories — use
  `scripts/ncc-memory.sh` or `scripts/ncc-memory.cmd`, which pin to
  the git root.
- Skill junctions → `.ncc/skills`: `.agents/skills`, `.devin/skills`,
  `.claude/skills` — all local and gitignored; recreate after fresh
  clones with `mklink /J <dir> .ncc\skills` (Windows) or
  `ln -s <abs>/.ncc/skills <dir>` (Unix).
- Project instincts live in `.devin/instincts/`; treat them as hints,
  not policy. Audit agent config changes with
  `agentshield scan --path .` before committing.
